# Jemma Wedgwood Portfolio

The approved white portfolio uses TanStack Start, React, Tailwind CSS and Cloudflare Workers. It keeps the home page, five project galleries, theme switch, and opportunity desk. Contact is through the email link only; no contact data is sent to a server.

## Local development

Use Node.js 22.12 or later and the pnpm version pinned in `package.json`.

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Open http://127.0.0.1:3001. Development runs through the Cloudflare Vite plugin in the local Workers runtime. For another port, run `pnpm images && pnpm exec vite dev --host 127.0.0.1 --port 3003 --strictPort`.

Copy `.env.example` to `.env` only if the canonical site URL needs to change. `VITE_SITE_URL` is public build-time configuration, used in social metadata and crawler routes. The default is `https://www.jemmawedgwood.co.za`.

## Checks and production preview

```sh
pnpm cf-typegen
pnpm build
pnpm check
pnpm preview
```

With the preview running, use another terminal:

```sh
pnpm test
pnpm exec wrangler deploy --dry-run
```

The smoke tests check the real local Worker: home page, project routes, 404 responses, static assets, metadata, crawler files and the opportunity desk. Set `SITE_TEST_URL` if the preview uses a different port.

`src/routeTree.gen.ts` is generated by TanStack Start and committed for type checks. `worker-configuration.d.ts` is generated by Wrangler and ignored. Run `pnpm cf-typegen` after changes to Worker bindings.

## Dylan's personal Cloudflare account

The deployment script selects the named `personal` Wrangler profile. This profile was verified against Dylan's personal account during migration. On a new machine, create that local profile with `pnpm exec wrangler auth create personal` and select the personal account. Do not commit login data or tokens.

```sh
pnpm run deploy:check
pnpm run deploy
```

`deploy:check` builds and checks the upload package without publishing. `deploy` builds and publishes the `jemma-website` Worker using `--profile personal`. Project and gallery photographs are generated as 480, 960, 1600 and 3200 pixel WebP files before development and production builds. Browser `srcset` selection replaces the Next.js image service; the original photos remain the source files. Gallery images are stored locally so visitors do not depend on Imgur.

The Cloudflare Vite plugin generates `dist/server/wrangler.json` and the static asset configuration. No database, Telegram token or application secret is needed.

Use `pnpm exec wrangler auth list` to check the local profile. Cloudflare API token environment variables override named profiles; ensure they target the same personal account if set. Add the final custom domain through Cloudflare after deployment. This repository does not change DNS.

Workers logs and traces are enabled. See the [Cloudflare TanStack Start guide](https://developers.cloudflare.com/workers/framework-guides/web-apps/tanstack-start/) for the supported deployment flow.

The existing `/opportunities` page remains excluded from indexing. It has no authentication; `noindex` is not access control.
